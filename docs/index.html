A neural-network-based C99 compiler, built from tables.

unisacc compiles C99 for Linux, macOS and Windows on x86-64 and arm64, writes the executables itself, and rebuilds itself byte for byte. Its compilation stages run on integer networks that are constructed from TSV tables and checked exhaustively, not trained.

unisacc

One file, six targets

unisacc.com runs on {Linux, macOS, Windows} × {x86-64, arm64} and writes ELF, Mach-O and PE executables directly, with no external assembler or linker.

Self-hosting

The released compiler rebuilds itself; each release checks that the rebuilt file is byte-identical (a fixed point).

C99 as written

Real projects such as jsmn, cJSON, miniz, stb, Lua and the c-testsuite corpus compile and run. Coverage is measured clause by clause against the standard.

Host libraries

On Linux and macOS, functions a program declares but does not define, such as getaddrinfo or libcurl, are forwarded to the system library.

How it works

Every table-shaped decision in the compiler (character classes, preprocessor directives, precedence, types, instruction selection, calling conventions) is answered by a small integer threshold network. The weights are derived deterministically from a TSV table DSL that describes finite state transitions.

  1. Tables. Each stage is written as TSV facts and manifests.
  2. Construction. A constructor turns the tables into networks. No gradient descent, no training data.
  3. Exhaustive check. Every network is verified over its whole input domain before it ships.
  4. Execution. A generic executor runs the networks stage by stage; a classic reference compiler is kept as a byte-for-byte referee.

Each release is signed for Windows (Authenticode) and notarized for macOS, and smoke-tested on six native machines after publishing.
